          Sessions recorded on the device itself and uploaded segment by segment
          to S3. Paginated with the shared list dialect, plus `streamKey` and
          `group`. The time filter matches sessions OVERLAPPING `[from, to)`,
          not just those started inside it, because a session spans a window.
          Each row carries computed rollups (`segmentCount`, `totalBytes`,
          `totalDurationMs`).


          Pass `group=runs` to paginate RECORDING RUNS instead of sessions: one
          drive with N cameras is N sessions, and a run is the set of sessions
          whose intervals are within 60 s of each other. Under `group=runs` the
          response returns `runs` instead of `sessions` (with members nested),
          `page.total` counts runs, and every filter selects which RUNS to
          return rather than which sessions to cluster. So `streamKey=cam0`
          returns the runs cam0 recorded in with all of their cameras present,
          and a from/to range returns overlapping runs whole rather than
          clipped.


          Listing also closes stale sessions as a side effect, which is why a
          session can flip from `open` to `closed` between two reads with
          nothing else having happened.
