      - content: >-
          The first-party dashboard's own path onto the live plane. It resolves
          the caller's Cognito identity from the bearer token and authorizes
          that identity to connect to the realtime broker and subscribe to
          `xorgate/devices/{deviceId}/telemetry`. Idempotent, so calling it on
          every page load is fine.


          **Third parties do not use this.** `POST /auth/live-credentials` is
          the third-party entry to the live plane: it needs no Cognito identity,
          works with any of the three credentials, and comes back scoped to the
          caller's organization or workspace. This operation exists because a
          browser federated through the identity pool is authorized by a
          different mechanism, and it is org-blind in what it lets you SUBSCRIBE
          to.


          **Use the returned `identityId` as the prefix of your client id.**
          Connect is scoped to `client/<identityId>*`, so a connection
          presenting any other client id is refused. Append something random
          after the identity id (xorgate-web uses `<identityId>-<role>-<uuid>`):
          one identity legitimately holds several concurrent connections, and
          two browser tabs of the same user resolve to the SAME identity id, so
          a bare identity id would make your own connections displace each
          other.


          Requires membership of at least one organization, not merely a valid
          token. Losing your last membership therefore ends live access rather
          than merely un-attaching something you could immediately re-attach.


          **Cognito ID token only.** The grant hangs off the caller's Cognito
          identity, which an API key does not have; a key is refused with `401
          USER_CREDENTIAL_REQUIRED`.
