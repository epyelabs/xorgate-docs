      - content: >-
          AWS IoT does not authorize MQTT for Cognito-federated principals
          through their IAM role. It requires an IoT policy attached to the
          Cognito IDENTITY. This endpoint resolves the caller's identity from
          the bearer token and attaches the browser policy to it, after which
          the browser can connect over MQTT-over-WSS and subscribe to
          `xorgate/devices/{deviceId}/telemetry`. Idempotent, so calling it on
          every page load is fine.


          **Use the returned `identityId` as the prefix of your MQTT client
          id.** The policy scopes `iot:Connect` to `client/<identityId>*`, so a
          CONNECT presenting any other client id is refused. Append something
          random after the identity id (xorgate-web uses
          `<identityId>-<role>-<uuid>`): one identity legitimately holds several
          concurrent connections, and two browser tabs of the same user resolve
          to the SAME identity id, so a bare identity id would make your own
          connections displace each other.


          Requires membership of at least one organization, not merely a valid
          token. Losing your last membership therefore ends live access rather
          than merely un-attaching a policy you could immediately re-attach.


          Note the current policy is org-blind in what it lets you SUBSCRIBE to:
          it authorizes the telemetry topic space broadly rather than per
          organization, so it is safe for first-party use and NOT yet safe to
          hand to a third party. Narrowing the subscribe scope is tracked as
          platform-readiness work. Connect scoping and revocation are done.


          **Cognito ID token only.** The grant attaches to the caller's Cognito
          identity, which an API key does not have; a key is refused with `401
          USER_CREDENTIAL_REQUIRED`. Live-plane access for key-authenticated
          consumers is separate work.
