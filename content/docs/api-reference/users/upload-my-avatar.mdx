          The image arrives as base64 in the body rather than through a
          presigned PUT: clients downscale to a 512px square first, so the
          payload is tens of kilobytes and one round trip writes both the object
          and the row that points at it.


          The declared `contentType` is checked against the bytes themselves — a
          payload whose magic number disagrees with its label is refused,
          because the declared type is what gets served back on the presigned
          GET. The stored object is private; the response carries a fresh
          `avatarUrl` for it.


          **Cognito ID token only.** An `xg_` API key is refused with `401
          USER_CREDENTIAL_REQUIRED`: this operation acts on a person, and a key
          has no user behind it.
