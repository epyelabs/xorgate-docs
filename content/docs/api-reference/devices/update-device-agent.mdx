      - content: "Publishes a one-shot update command over MQTT. The device starts a
          systemd one-shot that downloads the latest published build of the
          agent it runs (see GET /device-dist/latest, with `?agent=rust` for a
          device whose `agent` is `rust`), installs it, and restarts the agent,
          so the device drops offline while it restarts: typically seconds on a
          Rust device, roughly a minute or two on a JS device, longer on a slow
          link. Latest-only: there is no version parameter. A failed install
          rolls back, leaving the device on its current build. On a Rust device
          the same run then installs the extra OS packages a declared camera
          sensor needs (the `cameraSensors` config namespace), which can add
          minutes and never fails the update. IMPORTANT: 202 means the command
          reached the broker, NOT that the update succeeded, and the ack could
          not tell you either (the agent is restarted mid-update). Observe the
          outcome by polling GET /devices/{id}: `agentVersion` changes when a
          different build was installed. An UNCHANGED `agentVersion` after the
          device returns online has two meanings: the device was already on the
          latest build, which is a legitimate run (it reinstalls that build, and
          on a Rust device it is how missing camera packages get installed), or
          the install failed and rolled back. Compare `agentVersion` with GET
          /device-dist/latest to tell them apart, and read the updater's journal
          on the device for the detail: `journalctl -u xorgate-updater-rs` on a
          Rust device, `journalctl -u xorgate-updater` on a JS device. The
          device must be online (409 otherwise). Pressing this twice is
          harmless: `systemctl start` on an already-running one-shot coalesces
          into the run in flight."
