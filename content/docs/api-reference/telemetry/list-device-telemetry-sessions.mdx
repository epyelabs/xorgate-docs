          The index of what the device RECORDED, one row per telemetry session,
          with the counters and the `insights` block computed when its overview
          was built (distance, duration, max speed, stops, GPS quality, ...).
          This is the read for a sessions table or a roll-up such as "kilometres
          this month": it never opens an artifact and never touches object
          storage. No URLs; to play a session's telemetry, ask the replay
          manifest for its window.


          A telemetry session is NOT a video session: both ids are minted
          independently on the device, so relate them by time. `from`/`to` match
          sessions OVERLAPPING the range, exactly like `GET
          /devices/{id}/sessions`, so a recording run's distance is the sum over
          the telemetry sessions returned for the run's window. `insights` is
          `null` on a session whose overview has not been built yet (it is
          `open`, or closed within the last minute or so). Listing has the same
          side effect as the media list: it closes stale sessions as it goes.


          Paginated: `page.total` is exact. Sorted by session start, newest
          first by default.
