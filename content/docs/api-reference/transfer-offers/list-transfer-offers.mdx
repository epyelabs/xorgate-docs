          Offers your organization CREATED, plus offers it has already ACCEPTED,
          newest first. `direction` tells them apart.


          **There is no inbox of incoming pending offers, by design.** An offer
          names no destination — that is exactly what lets it be handed to an
          organization whose id the sender does not know — so a pending offer is
          discoverable only by its code. If someone has offered you a device,
          you will have been sent a code; read it with `GET
          /transfer-offers/{code}`.


          Declines are visible here: an offer the destination refused reads
          `declined` with `resolvedAt` set, rather than quietly expiring.
