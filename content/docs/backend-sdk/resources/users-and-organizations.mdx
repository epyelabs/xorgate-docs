## `xg.me()`

```ts
me(): Promise<Me>
```

The bootstrap call. Resolves the credential to a user, creating the row on first
sight, and returns every organization the caller belongs to. It is the only
org-aware endpoint that never needs the tenancy header, which is why it is also
available on the [bootstrap client](/docs/backend-sdk/installation).

```ts
const { user, memberships, organizations } = await xg.me()

console.log(user.email, user.role) // "ops@acme.co" "user"
console.log(organizations.map((o) => o.slug)) // ["acme-fleet"]
```

`memberships` here are the plain rows. The enriched roster, with each member's
identity attached, comes from `xg.memberships.list()`.

`organizations` is empty for a brand-new user. Create one before calling
anything org-scoped.

<Callout title="Normalized casing">
  `user.createdAt` and `organization.createdAt` / `updatedAt` are `created_at`
  and `updated_at` on the wire, because those rows serialize straight out of
  Postgres. The SDK normalizes them, like the other snake_case outliers.
</Callout>

Maps to [`GET /me`](/docs/api-reference/users/get-me).

## `xg.organizations`

The organization is the tenant boundary. Workspaces, devices, telemetry, media
and API keys live inside exactly one and never cross.

```ts
list(params?: ListOrganizationsParams): Promise<Organization[]>
listAll(params?): Promise<Organization[]>
iterate(params?): AsyncIterableIterator<Organization>
get(id: string): Promise<Organization>
create(input: CreateOrganizationInput): Promise<Organization>
update(id: string, input: UpdateOrganizationInput): Promise<Organization>
delete(id: string): Promise<void>
```

### `list(params?)`

Every organization the caller is a member of. Paginated with the
[shared list dialect](/docs/backend-sdk/pagination); a user belongs to a
handful at most, so one default page is effectively all of them, and
`listAll()` is the guaranteed-complete form.

### `get(id)`

<Callout type="warn" title="id must be the ACTIVE organization">

`get()` only reads the organization the client is configured for. Reading a
different one you belong to means switching clients, not changing the argument:

```ts
const other = xg.forOrganization(otherId)
const org = await other.organizations.get(otherId)
```

Passing an id that is not the active organization is a `403 FORBIDDEN`, not a
cross-organization read.

</Callout>

### `create(input)`

```ts
const org = await xg.organizations.create({
  name: "Acme Fleet",
  slug: "acme-fleet", // unique across ALL organizations
})
```

Creates the organization and inserts a membership with `role: "owner"` for the
caller. It does not need an active organization, which makes it the one write a
brand-new user can perform, and why it is on the bootstrap client too.

### `update(id, input)`

Partial: send only what changes. An empty object is a `400`. Owner or admin.

### `delete(id)`

Cascades to workspaces, devices, API keys and memberships. There is no undo and
no soft delete. Owner only.

Maps to the
[Organizations endpoints](/docs/api-reference/organizations).

## `xg.memberships`

```ts
list(params?: ListMembershipsParams): Promise<MembershipWithUser[]>
listAll(params?): Promise<MembershipWithUser[]>
iterate(params?): AsyncIterableIterator<MembershipWithUser>
add(input: AddMembershipInput): Promise<AddMembershipResult>
updateRole(membershipId: string, role: MembershipRole): Promise<Membership>
remove(membershipId: string): Promise<void>
```

### `list(params?)`

The roster for the active organization, each row enriched with its member's
`user` so a UI renders names and emails without a second round trip. Paginated
with the [shared list dialect](/docs/backend-sdk/pagination); the default order
is **ascending by join date**, the one list whose default is not `desc`.
`list()` returns one request's worth (up to `limit`, default 100);
`listAll()` is the guaranteed-complete form.

```ts
for (const m of await xg.memberships.list()) {
  console.log(m.role, m.user?.email ?? m.userId)
}
```

`user` is typed nullable because the schema allows it, but a membership cascades
with its user, so in practice it is always present.

### `add(input)`

Adds a member by `userId` or by `email`. The two are mutually exclusive in the
type.

```ts
// Existing xorgate user.
await xg.memberships.add({ userId: "9c2f...", role: "member" })

// By email. Provisions a Cognito account if there is none.
const { membership, invited } = await xg.memberships.add({
  email: "new.operator@acme.co",
  role: "admin",
})

if (invited) {
  // A new account was created and emailed a temporary password to set on
  // first sign-in. Nothing further for you to send.
}
```

`role` defaults to `member`. Adding someone who is already a member is a `400`,
not a no-op, so guard on the roster if you are reconciling a list.

Owner or admin.

### `updateRole(membershipId, role)`

Changes a member's role in place, keeping their membership id and `createdAt`.
(Before this existed, the only way was `remove()` then `add()`, which briefly
left the member with no access.)

```ts
const membership = await xg.memberships.updateRole("m-9c2f...", "admin")
```

Owner or admin, with two extra gates the API enforces:

- **Owner-level changes need an owner.** Granting `owner`, or changing an
  existing owner's role, is a `403` unless the caller is an owner themselves;
  an admin cannot promote anyone (or themselves) past the gate.
- **The last owner cannot be demoted.** A `403`, same as `remove()`, so an
  organization can never lock itself out.

Setting the role a member already has is a no-op `200`.

### `remove(membershipId)`

Takes the **membership** id, not the user id. Removing the last remaining owner
is refused with a `403`, so an organization can never be left ownerless.

Maps to the [Memberships endpoints](/docs/api-reference/memberships).

## `xg.search(q)`

```ts
search(q: string, options?: { signal?: AbortSignal }): Promise<SearchResult[]>
```

A jump-to-detail navigator, not a result browser. It matches devices by name or
serial, returns at most 6 hits per resource type, and normalizes every hit to one
shape so a single code path renders them all.

```ts
const hits = await xg.search("XG-0042")

for (const hit of hits) {
  if (hit.type === "device") {
    const device = await xg.devices.get(hit.id)
  }
}
```

A `q` shorter than two characters returns an empty array rather than an error,
and `%` and `_` are matched literally rather than as wildcards.

`SearchResult.type` includes `workflow-template` and `workflow-instance`. The
endpoint returns those, and the SDK does not filter them out, but their resources
are not part of this SDK's surface. Treat any hit that is not a `device` as
something you cannot follow.

Maps to [`GET /search`](/docs/api-reference/search/search).
