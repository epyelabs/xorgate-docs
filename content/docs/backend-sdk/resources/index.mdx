## Method index

Role column, verified against the handlers rather than the spec, which does not
state most of these:

- **any**: any valid credential. No organization role is checked.
- **read**: any membership role, `viewer` included.
- **write**: `owner`, `admin` or `member`. A `viewer` gets `INSUFFICIENT_ROLE`.
- **owner/admin**: exactly those two.
- **owner**: owner only.
- **platform admin**: `user.role === "admin"`, unrelated to any membership.
- **API key only**: refuses a user token and a session token alike.

Two orderings are worth knowing before you write error handling, because both
were confirmed against production. The **role gate fires before the state
check**: a `member` key calling `reboot()` on an OFFLINE device gets
`INSUFFICIENT_ROLE`, not `CONFLICT`, so a service account that is only a member
never sees the offline branch at all. And the **credential-shape refusals happen
before any lookup**, so `USER_CREDENTIAL_REQUIRED` and `API_KEY_REQUIRED` are
decided on the token's prefix and are safe to branch on.

## Not modelled

`POST /live/access` and `DELETE /live/access` have no SDK method. Both act
on the **caller's own** Cognito identity, granting and revoking a browser's
ability to subscribe to live telemetry, which makes them meaningless from a
server. They belong to the frontend SDK. See
[What this SDK does not cover](/backend-sdk/not-covered).

`POST /device-registrations/{code}/claim` and `GET /get/{code}` have no SDK
method either. They are the install script's private contract, called on the
device, and the claim route returns X.509 private key material.

The workflow AUTHORING endpoints are not modelled: creating a template, saving
a draft, publishing or restoring a version, attaching a template to a device,
triggering runs and reading them, the node catalog, the model registry,
simulations and per-organization credentials. Only the three template reads
above are, because a program discovers templates by tag; a template is authored
in the web editor. That surface is still moving, and `xg.request()` reaches it
with no stability promise.
